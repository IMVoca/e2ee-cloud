# E2EE 迷你雲端與惡意伺服器攻擊重現（Group 8）

論文：J. Hofmann, K. T. Truong, "End-to-End Encrypted Cloud Storage in the Wild: A Broken Ecosystem," ACM CCS 2024

- **研究目標**：以自建系統證明「只加密、不認證」不足以保護雲端檔案，並驗證加入認證加密後可偵測上述攻擊
- **威脅模型**：攻擊者為惡意或被入侵的伺服器，可讀取、修改、新增、對調所有儲存的密文與中繼資料，但取得不了使用者密碼與金鑰
- **重現主張**：未認證的加密雲端無法阻止惡意伺服器竄改或偽造檔案
- **重現分級**：Tier B，以本機自建的小型系統重現相同攻擊機制

## 實作內容（Python，本機執行）

| 項目 | 內容 | 檔案 | 負責 |
|---|---|---|---|
| 1. 金鑰產生 | 由密碼推導主金鑰（PBKDF2-SHA256），每個檔案另配隨機檔案金鑰 | `common/kdf.py` | C |
| 2. 模擬雲端伺服器 | 以資料夾儲存密文；提供上傳、下載、列出檔案 | `server/storage.py` | C |
| 3. 客戶端 V1（有漏洞） | AES-CBC 加密、不做認證、檔名以明文存放 | `v1/client.py` | C |
| 4. 客戶端 V2（修正版） | AES-GCM 認證加密，檔名綁定驗證資料，檔案清單加 HMAC | `v2/client.py` | C |
| 5. 惡意伺服器 | 模擬竄改檔案內容、植入偽造檔案、對調檔名；無法取得密碼或金鑰 | `server/malicious.py` | D |
| 6. 展示程式 | 一鍵執行「V1 正常 → V1 受攻擊 → V2 受攻擊」並列出結果 | `demo.py` | D |

## 驗收內容（皆以 pytest 自動化測試，`tests/test_acceptance.py`，負責：D）

| 驗收項目 | V1（有漏洞） | V2（修正版） |
|---|---|---|
| 正常上傳後下載 | 內容與原檔一致 | 內容與原檔一致 |
| 伺服器竄改檔案內容 | 未察覺，接受錯誤內容 | 偵測並拒絕 |
| 伺服器植入偽造檔案 | 清單出現偽造檔 | 偵測並拒絕 |
| 伺服器對調檔名 | 開啟 A 得到 B 的內容 | 偵測並拒絕 |

測試目前都標記 skip，對應功能完成後移除 skip。

## 安裝與執行

```bash
pip install -r requirements.txt
pytest              # 執行驗收測試
python demo.py      # 展示程式（完成後）
```
